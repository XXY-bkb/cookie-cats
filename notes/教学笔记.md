> 这份文档是"陪跑版"：不只告诉你结论，还告诉你**每一块为什么这样写、坑在哪、自己动手时的顺序**。
> 建议配合 `notebooks/01_eda.ipynb`、`notebooks/02_test.ipynb` 一起看——notebook 是讲解版，
> `src/` 是工程版，两者刻意分工。

## 0. 先建立正确的心智模型

一个 A/B 分析项目，真正的顺序是：

```
业务问题 → 指标定义 → 数据体检 → 设计检查（SRM/样本量） → 主指标检验
        → 护栏指标 → 分层/异质性 → 敏感性 → 决策建议 → 一页纸
```

代码结构应该跟这个顺序一一对应。**先写结论、再补代码**是本末倒置；
但**先跑数、再想指标**同样危险——你会不自觉地挑一个显著的指标讲故事（p-hacking）。

本项目的三条硬规则（写进 README 和 docstring，方便别人 review）：

1. 差值方向统一为「对照组 − 实验组」，正数代表对照更好；
2. 随机过程必须有 `seed`，任何数字都要能重跑；
3. "正确行为"写成单元测试，而不是口头说明。

## 1. 项目骨架：为什么这样分目录

```
src/stats_utils.py   纯函数 + dataclass，不读文件、不画图、不 print 结论
src/analysis.py      管道：读数据 → 调 stats_utils → 写 results.json + 图
src/plots.py         所有图集中在这里，报告脚本复用
notebooks/           讲解与探索，可以重复、可以不优雅
tests/               对 stats_utils 的断言
reports/             产物（json / png / pdf），不进 .gitignore
```

**为什么要分？** 因为改一个数字时，你只希望改一处。

- 如果把检验代码抄在 notebook 里，改了公式就得改三个地方，迟早有一个忘了；
- 如果 `stats_utils` 里混进 `print` 和画图，就没法在被别的脚本 import 时保持安静；
- 如果结论只存在于 notebook 输出里，报告脚本就只能手抄数字，抄错没人发现。

**入口设计**：`python -m src.analysis`。`-m` 把项目根目录放进 `sys.path`，
所以 `from src.stats_utils import ...` 能工作。直接 `python src/analysis.py` 会失败（找不到 `src` 包），
这是新手最常踩的坑之一。

**路径处理**：一律用 `pathlib`，且以文件位置为锚：

```python
ROOT = Path(__file__).resolve().parents[1]   # analysis.py 在 src/ 下，上一级就是项目根
DATA = ROOT / "data" / "raw" / "cookie_cats.csv"
```

这样无论从哪个目录运行，路径都对。不要用 `"../data/..."` 这种相对当前工作目录的写法。

## 2. 统计原理：五块必须真懂的东西

### 2.1 SRM：先确认"分流没坏"

**直觉**：两组人数应该接近 1:1。差太多，说明分流 bug，后面的指标差异可能来自"分到了不同的人"。

**公式**：卡方拟合优度

```
chi2 = Σ (观测人数 - 期望人数)² / 期望人数
```

**代码**（`stats_utils.srm_check`）：传人数，算期望，交给 `scipy.stats.chisquare`。

**本项目的坑**：p=0.0086 < 0.05，"技术上不通过"；但两组只差 0.87%。
**大样本下，统计显著 ≠ 业务异常**。所以 `SRMResult` 同时给 `passed` 和 `max_relative_gap`，
报告里两个都写。面试时这样答："先排查分流日志；偏差 0.87% 对 0.8pp 的效应影响有限，但不假装没看见。"

### 2.2 两比例 z 检验：主指标怎么比

**直觉**：两组留存率之差，除以"这个差值的标准误"，得到 z；z 够大就说明差值不像噪声。

**两个标准误，别搞混**：

```
检验用（合并）: SE_pooled   = sqrt(p_pool(1-p_pool)(1/n1 + 1/n2))
区间用（不合并）: SE_unpooled = sqrt(p1(1-p1)/n1 + p2(1-p2)/n2)
```

为什么检验要合并？因为零假设是"两组同一个 p"，合并样本估计更准。
为什么区间不合并？因为区间描述的是"差值本身"的波动，两组各自的比例都要估计。

**代码**：

```python
p_c, p_t = x_control / n_control, x_treatment / n_treatment
diff = p_c - p_t
se = np.sqrt(p_c * (1 - p_c) / n_control + p_t * (1 - p_t) / n_treatment)
ci_low, ci_high = diff - 1.96 * se, diff + 1.96 * se
z_stat, p_value = proportions_ztest([x_control, x_treatment], [n_control, n_treatment])
```

**自己写时的验证方法**：手算一遍 z 和 p，和库函数对比（`02_test.ipynb` 第 3 个代码格就是这么做的）。
对上了，才说明你真的懂这个检验，而不是会调包。

### 2.3 置信区间：业务真正要看的东西

- **Wald 区间**：`diff ± 1.96 * SE`，简单，但比例接近 0/1 时会越界；
- **Wilson 区间**：单组比例用，解一个二次方程，永远落在 [0,1]；
- **Newcombe 区间**：两个 Wilson 区间拼出差值的区间，作为 Wald 的稳健性备选。

本项目的态度：主报告用 Wald（和 Newcombe 一致），单组柱状图误差线用 Wilson。
**报告里写"两种方法结论一致"，比只写一种更有说服力。**

### 2.4 Bootstrap：中位数这种"没有公式"的统计量

**直觉**：把样本当总体，反复有放回抽样，每次算一个中位数差，得到"差值"的分布，
取 2.5% 和 97.5% 分位数就是 95% 区间。

**为什么局数要用它**：中位数没有简单的标准误公式；且分布极端长尾，正态假设不成立。

**代码要点**：

```python
rng = np.random.default_rng(seed)
diffs = np.empty(n_boot)
for i in range(n_boot):
    a = rng.choice(control, size=len(control), replace=True)
    b = rng.choice(treatment, size=len(treatment), replace=True)
    diffs[i] = stat(a) - stat(b)
ci_low, ci_high = np.percentile(diffs, [2.5, 97.5])
```

**坑**：`np.random.seed` 是全局状态，会污染别的代码；用 `default_rng` 独立实例。
**性能**：45k 样本 × 2000 次约 10-20 秒，能接受；再大就考虑向量化或降 `n_boot`。

### 2.5 分层、标准化与辛普森悖论

**直觉**：整体差异可能由"两组玩家结构不同"造成。分层后如果每个桶方向一致，结论更稳；
如果方向翻转，就是辛普森悖论。

**直接标准化**：用对照组的桶占比 `w` 当权重，分别算两组的加权平均：

```
std_c = Σ w_i * rate_c_i
std_t = Σ w_i * rate_t_i
```

**交互检验**：逻辑回归里加 `C(grp) * C(bin)`，和只有主效应的模型比似然比：

```
LR = 2 * (llf_inter - llf_main) ~ chi2(df = 交互项个数)
```

**本项目的关键判断**：分层变量"局数"是**实验后变量**（版本可能影响局数），
所以分层只能描述"效应在谁身上更大"，不能解释"改版是否通过增加局数提升留存"。
这一点写进 README 的局限，是加分项，不是减分项。

### 2.6 功效、MDE、样本量

**直觉**：功效 = "如果真有 δ 的效应，这次实验能检出的概率"。

**三个公式（比例指标，用 Cohen's h）**：

```
h = 2*arcsin(sqrt(p1)) - 2*arcsin(sqrt(p2))
n_per_group = solve_power(effect_size=h, alpha=0.05, power=0.8, ratio=1)
MDE = 反解：找到 δ 使 power(δ, n) = 0.8
```

**本项目的数字**：每组 44,700 人，对 0.82pp 的功效 88%，MDE 0.73pp；
要检出 0.5pp 需要每组 94,471 人。

**最容易犯的错**：用观测到的效应反算功效，然后说"实验功效 88%，所以设计很好"。
这是**事后功效**，只能参考。正确做法是事前按"业务最小可感知效应"算样本量。

### 2.7 多重比较

测 k 个指标、每个都用 α=0.05，至少一个假阳性的概率是 `1-(1-α)^k`。
5 个指标时约 23%。Bonferroni 把阈值改成 `α/k`，最保守；更精细的有 Holm、BH（控制 FDR）。

**本项目的处理**：主指标 + 次日留存两个检验，α 调到 0.025；7 日留存仍显著，次日留存仍不显著。
结论没变，但流程上必须做——**面试官会问这个**。

## 3. 代码怎么读：三个值得模仿的写法

### 3.1 用 dataclass 返回结果，而不是 tuple

```python
@dataclass(frozen=True)
class ProportionTest:
    ...
    @property
    def significant(self) -> bool:
        return self.p_value < self.alpha
```

好处：

- 调用方写 `res.ci_low`，不用记"第 6 个返回值是区间下界"；
- `frozen=True` 让结果不可变，避免下游误改；
- 派生量用 `@property`（`significant`、`ci_excludes_zero`），不会出现"存了但没更新"的脏字段。

### 3.2 用异常把"不可能"挡在入口

```python
if n_control <= 0 or n_treatment <= 0:
    raise ValueError("样本量必须为正")
if not (0 <= x_control <= n_control and 0 <= x_treatment <= n_treatment):
    raise ValueError("成功数必须落在 [0, n] 区间")
```

统计函数最怕"静默算出一个 NaN"。宁可早崩，也不要让错误数字流进报告。

### 3.3 图：所有"读者可能误解的地方"都要标注

- y 轴截断必须写"y 轴自 17.5% 起"；
- ECDF 用 `symlog` 而不是 `log`，因为数据里有 0 局（log(0) 不存在）；
- 百分比轴用 `PercentFormatter(1.0)`，不要手写 `*100` 再拼 `%`；
- 误差线必须画，否则读者以为柱高就是真值。

**中文乱码**只要两行：

```python
plt.rcParams["font.sans-serif"] = ["Microsoft YaHei", "SimHei", "DejaVu Sans"]
plt.rcParams["axes.unicode_minus"] = False
```

## 5. 本机踩过的坑（你也会遇到）

| 现象 | 原因 | 解法 |
| --- | --- | --- |
| `pip install` 报 `[Errno 13] Permission denied` | 沙箱不允许 pip 在临时目录 rename/delete | 手工下载 wheel 解压到 `.pylibs`，或换一台机器/虚拟环境 |
| `ModuleNotFoundError: statsmodels` | 装到了非默认路径 | 运行时设 `PYTHONPATH`，或在代码里 `sys.path.insert` |
| 中文图全是方框 | 默认字体没有中文 | 设 `font.sans-serif` 为 Microsoft YaHei / SimHei |
| `python src/analysis.py` 报 `No module named src` | `sys.path` 不含项目根 | 用 `python -m src.analysis` |
| notebook 里 import src 失败 | 工作目录是 notebooks/ | `sys.path.insert(0, str(Path.cwd().parent))` |
| 输出中文乱码 | 控制台编码不是 UTF-8 | `$env:PYTHONIOENCODING='utf-8'` + `[Console]::OutputEncoding` |
| PowerShell 里 heredoc 报错 | PowerShell 不支持 `<<'EOF'` | 用 `@'...'@` 或直接写文件 |
| 图例挡住数据 | 默认位置不智能 | `loc` 手动指定，或放图外 |

## 7. 做完之后，下一步练什么

- **换指标**：如果有收入数据，练"留存 vs ARPU"的取舍（护栏指标）；
- **换设计**：序贯检验 / CUPED 方差缩减（用实验前数据降方差）；
- **换方法**：贝叶斯 A/B（直接给"B 更好的概率"和期望损失）；
- **换表达**：把一页纸做成 5 页 deck，练"给不同受众讲同一个结论"。

最重要的是：**每做一个项目，都把"结论 + 区间 + 局限 + 决策"四件套写全**。
这四件套比任何模型都更能体现你懂业务。
